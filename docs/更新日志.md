# 更新日志

## 0.2.0

### 单场景生成改用 Pi Agent Core

单场景生成从 LangChain、LangGraph 切换到 Pi Agent Core。Pi 使用你配置的模型，根据画布上的材料写出场景候选。工作台读回脚本供你预览；接受前，正式作品保持原样。

- 想试另一种写法时，可以从 AI 历史中的候选分叉。新分支不会覆盖原稿；即使接受了分支，仍能回到原任务继续处理。
- 生成中断后，重新打开工程不会自动调用模型重写。工作台先核对已保存的草稿、候选和提交记录。遇到「结果待核对」，可从 AI 历史找回操作，不必重复创建分支。
- 从旧版升级前，建议备份工程，先处理未结束的生成任务。无法确认进度的旧任务不会自动续写。

### 启动阻断的生命周期入列（2026-11-22，场景生成）

- 工作台状态机把当前状态权威同时用于发现列表：启动成功、运行/等待进度、切换视图时，已知会阻止普通启动的非终态 `generate` 立即进入/更新“需要处理的操作”；终态立即移除。空抽屉首次加载后启动 A、A 等待、分叉进入 B、接受 B 至终态时，A 无需预置或手动刷新仍在列表，可选中并按原权限处理。
- 发现读回与本地事实合并：读回启动后才出现的阻断不会被过期空列表抹掉；读回启动前已知、之后新读回不再列出的阻断会被视为外部已处理而移除；迟到的旧读取不覆盖已应用的新读取。进度 tick 只做本地合并，不查磁盘。
- `refreshDiscovery` 改为可等待 `{ ok: true } | { ok: false; message }`：读取失败、异常或作用域已切换返回可直接展示的失败信号，供历史未知核对在真正完成后才显示“已重新读取”。
- 新增 jsdom 真实状态机生命周期测试（发现列表始终为空，不预置 A、不手动刷新）：A 自动入列、B 终态时启动不保存不发 IPC、处理 A 后解除；另覆盖读回前启动窗口、读取失败信号和旧读取迟到不复活阻断。定向测试与 Node／Web 类型检查通过；未打开页面、Electron 或真实用户目录。

### 启动阻断发现与终态失效（2026-11-22，场景生成）

- “需要处理的操作”发现范围补上所有会阻止同场景普通生成的非终态 `generate`，包括已有检查点的等待审阅与安全暂停；行本身不因此标成“可继续”或“待核对”，选中只切到当前视图，按原有交互/取消/继续权限处理。分叉（缺 `mode`）、修复和 `validate` 仍不占生成位置。
- 收到同 scope 同操作的权威终态后，`useGenerationStatus` 立即把该操作从发现列表移除，并记入本作用域的终态集合；迟到的历史发现响应经同一集合过滤，不能复活旧阻断项。集合只排斥同操作终态旧项，之后发现的新操作仍照常进入列表；切场景即重置。
- 工作台“需要处理的操作”说明同步改为“会阻止新生成的进行中记录也能从这里打开”，不再暗示列表只含无检查点遗留或待核对记录。
- 真实装配回归：生成 A 至 waiting（有检查点）→ 从 A 分叉并接受 B → B 为当前终态时，发现列表仍含 A、`blocksNewGeneration` 为真且启动原因在保存/start 前给出；取消 A 后重新发现不含旧项，C 生成至终态仍正常。jsdom 真实状态机补充取消 A 后旧发现响应不复活、C 终态不误挡、后继新 D 仍被发现的用例。
- 定向单测、真实装配集成测试与 Node／Web 类型检查通过；未打开页面、Electron 或真实用户目录。

### 已有生成阻断普通启动（2026-11-22，场景生成）

- 渲染状态新增可选 `blocksNewGeneration`，由启动预检的同一 `isActiveGenerationExecution` 投影：只有非终态 `generate` 为真，缺少 `mode` 的分叉、`repair`／`validate` 与终态都不占位。普通启动不再用“未完成列表非空”或“当前记录非终态”猜测冲突。

- 修复重跑使用独立禁用依据：画布／工作区前提与启动相同，但不含已有生成冲突，合法 repair 不被一起禁掉；分叉入口不变。后端 `requireNoActiveGeneration` 最终重核保留。
- 阻断事实随数据实时派生：同一操作的新状态覆盖旧未完成列表项；重载读到不再阻断的列表后原因解除、启动恢复可用。
- 专属测试：应用层投影按 `state × mode` 断言；表现层断言列表非空不冒充、旧列表项不覆盖终态；jsdom 真实 `useSceneGeneration` 覆盖“选中终态 + pending generate 拒绝保存／启动”“repair 与缺 mode 分叉不阻断”“重载后恢复”，以及终态气泡／失败气泡的真实原因、AI 历史入口和修复确认不被启动冲突禁用。真实装配测试同时断言活跃 generate 带阻断、分叉／修复遗留不带阻断。定向单测、集成测试与 Node／Web 类型检查通过；未打开页面、Electron 或真实用户目录。

### 启动顺序与状态核对（2026-11-22，场景生成）

- 首次或重载读取尚未落地时，“场景任务状态核对中/核对失败”与画布保存、已有任务共用同一 start 门禁：空态按钮与实际 `start` 都按该原因禁用，首帧和切场景都不会在未知状态上发送保存或启动。
- 启动按场景登记在途请求：读回把视图从空态切到旧操作后再次点击不会多发一次 start；准备和保存期间用同一门禁实时复核，读回发现已有活动任务时不再发出启动。
- 区分“读回更新”与“作者显式切换”：只有切场景、从待处理列表选任务，以及动作成功安装另一个操作的视图（启动、修复重跑、分叉）会让此前已派发的启动失去写回资格。被动读回后成功会采纳新操作并把进度订阅切到它，失败（含保存抛错）仍可见；显式切走后不强制跳回，改用固定提示保留原动作归属。
- 作者动作成功并明确进入另一个操作时统一登记显式切换，不按分叉先后顺序特判：分叉先成功时，迟到的启动成功不抢回分叉视图、失败不贴到分叉；启动先成功时，随后分叉只返回“未切换、可刷新找回”的既有结果；分叉失败不算成功切换。
- 已派发启动的确认失败与丢回执不再只写当前视图的内联错误：固定提示提升为页级通知宿主，历史标签打开或生成面板隐藏时仍会转成真实 toast；未知结果只提示“待确认、可能已开始”，不写成确认失败，也不引导直接重试。
- 显式切走后启动以 `communicationFailed` 结束时同样使用“结果待确认”提示；确认失败与结果未知分别告知，后续切视图不会抹掉已发出的提示。
- 状态 hook 只凭后端结构化的 `sceneGenerationOperationMissing` 清除显式选择；旧检查点缺失/损坏、身份不符和通信失败保留选择与当前视图，只显示目标读取错误。回退到记录与回退为空分别提示。
- 新增真实 React 宿主（jsdom + `useSceneGeneration`）延迟测试：首次读取挂起、`saveCanvas` 前后读回、`client.start` 前后读回、启动失败与保存抛错、显式换任务/场景、待处理列表选择与旧检查点读取失败；并补齐“分叉先/启动先 × 成功/确认失败/丢回执”的确定性矩阵，启动先成功时旧分叉结果仍以既有提示返回。另在 jsdom 挂载页级通知宿主与真实 sonner `Toaster`，证明历史标签打开时提示确实发出、切视图不抹掉、同类提示按固定 id 替换而不堆叠。Web 定向类型检查与相关单测通过。

### 待核对发现与历史分页（2026-11-22，场景生成）

- 工作台“需要处理的操作”不再只按检查点缺失发现：真实恢复产生的 `writeUnknown`／`commitUnknown` 即使带合成或真实检查点也进入发现列表；来源记录更新更晚、普通历史同屏存在都不会遮蔽；活跃代次仍不开放继续或核对。
- 发现查询改为独立的 `operationId` 游标分页（页大小 1..100，缺省 100），与历史 `checkpointId` 游标分开传输且同一请求互斥；101 条时返回 100 条和 `unfinishedNextCursor`，工作台加载器合并全部页后第 101 条仍可选中，响应不会越出 schema 或静默丢条。
- 单条检查点不可读只降级该条继续资格，不影响同页其它待处理条目和历史读取。
- 真实装配测试：分叉来源证据丢失后由 `GenerationRecovery` 产生写入待核对（不手清检查点）、提交回执不明产生提交待核对、来源推进更晚、同场景多任务、101 条分页和真实 controller/client schema；Node/Web 双类型检查通过。未启动 Electron／浏览器／页面。

### 待核对结果显式核对（2026-11-22，场景生成）

- 新增工作台“核对结果”动作，仅在 `state=interrupted` 且 `interruptReason` 为 `writeUnknown`／`commitUnknown`、无活动代次时出现；后端按五元操作身份、线程串行重新读取真实提交事实、写入回执、不可变草稿与工作区归属。
- 已证明提交时只按原 `commitId` 结算并保留既有清理重试语义，不新增提交；已证明写入时绑定候选并进入既有候选校验／审阅门，不新增模型调用；证据不足或只证明未写／未提交时维持待核对，执行记录、候选、工作区和账本不变。
- 核对不授予取消、终止、删除、归档或普通续跑权限；旧记录不会因核对获得新权限。工作台只展示后端返回的固定结论和安全文案，不从状态或错误文案推断。
- 复用既有 resume IPC 通道（`recovery:'verify'`），不新增冻结桥接方法；渲染状态新增可选 `canVerifyResult`，与后端入口共用同一判据。
- 无检查点恢复准入抽成单一 `unfinishedRecoveryIssue`，状态投影与应用入口不再逐条复制条件。
- 新增真实装配下的写入恢复、证据不足、提交结算、未提交保持、迟到重复请求、伪造身份和冻结通道入口测试；Node/Web 双类型检查通过。未启动 Electron／浏览器／页面，未调用真实模型。
